# Threat model

This model covers the local web application, Tauri shell, portable workspace boundary, and dependency supply chain. It is a release handoff document, not a penetration-test report.

## Assets and trust zones

| Zone               | Assets                                                                   | Trust assumption                                                                                                             |
| ------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| User workspace     | CSV/JSON/Markdown, native files, themes, object topology, start metadata | User owns the local copy; files may be malformed or intentionally hostile when imported.                                     |
| Browser/WebView    | Rendered content, selection, commands, in-memory undo state              | Content is untrusted input; browser and WebView behavior must remain the enforcement boundary.                               |
| Native shell       | IPC commands, filesystem paths, cache, WAL/checkpoint, asset handles     | Native code is privileged relative to the webview and must validate every request.                                           |
| Build supply chain | npm and Cargo packages, lockfiles, generated bundles                     | Registry metadata and artifacts can change or be compromised; lockfiles constrain resolution but do not prove source safety. |
| Release channel    | installers, bundles, SBOMs, notices, signatures                          | No signing identity, provenance service, or legal owner is evidenced yet.                                                    |

## Threats and controls

| ID  | Threat                                                                                                | Current control/evidence                                                                                                                                                                                                                                                                       | Residual risk or required follow-up                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | ZIP path traversal writes outside the import destination.                                             | Archive paths reject absolute, drive-qualified, empty, dot, dot-dot, control-character, and overlong components; extraction is staged.                                                                                                                                                         | Retain malicious-archive fixtures and run native tests on every supported OS.                                                                  |
| T2  | Decompression or resource exhaustion consumes memory/disk.                                            | Portable limits bound entries, entry sizes, total size, object count, cell count, asset sizes, and compression ratio.                                                                                                                                                                          | Review limits against real large workspaces and platform memory budgets before release.                                                        |
| T3  | Dangling, duplicate, cyclic, or forged embedded links corrupt topology.                               | v4 validation checks IDs/references; browser repair is deterministic and records containment/alias relations.                                                                                                                                                                                  | Add a user-facing repair report and test adversarial alias graphs before promising recovery.                                                   |
| T4  | Malformed JSON/CSV/Markdown or native assets trigger parser or renderer bugs.                         | Native codecs reject malformed structures; asset reads avoid data URLs at the Tauri boundary.                                                                                                                                                                                                  | Review HTML/SVG/PDF/media isolation and content sanitization per renderer; no complete audit is evidenced here.                                |
| T5  | Web content reaches a privileged native command or remote capability.                                 | Main capability has no permissions or remote scope; global Tauri API and asset protocol are disabled; production CSP has no network source.                                                                                                                                                    | Recheck every new command/capability and run native WebView smoke tests on Windows, macOS, and Ubuntu.                                         |
| T6  | IPC replay, stale acknowledgement, or confused workspace identity applies an edit to the wrong state. | Typed contracts carry workspace/revision IDs; adapter rejects stale or mismatched acknowledgements and validates response envelopes.                                                                                                                                                           | Native command implementation and multi-window/concurrency behavior need release-level testing.                                                |
| T7  | Cache corruption or torn writes cause data loss.                                                      | The recovery scaffold has acknowledged WAL frames, checksum validation, atomic checkpoints, replay, torn-tail repair, migration rollback, and portable rebuild. A private rusqlite service also enables SQLite WAL, full synchronous writes, transactional records, metadata, and checkpoints. | Full Tauri persistence integration and cross-platform durability evidence remain open; portable export and restore remain the safety boundary. |
| T8  | Dependency compromise or unreviewed license obligation enters a release.                              | npm and Cargo lockfiles are committed; deterministic SBOM/inventory artifacts and npm audit are part of the handoff.                                                                                                                                                                           | Run native advisory scanning, review source/artifacts, collect license texts, and assign legal acceptance.                                     |
| T9  | Sensitive workspace data is disclosed through diagnostics or public reports.                          | Storage errors avoid raw paths; contributor guidance asks for redaction.                                                                                                                                                                                                                       | Define telemetry policy (currently no core cloud telemetry is evidenced), private intake, log retention, and support workflow.                 |
| T10 | Unsigned or tampered release is installed.                                                            | No signing or provenance control is evidenced.                                                                                                                                                                                                                                                 | Release owner must choose key custody, signing, verification instructions, and artifact provenance before publication.                         |

## Security invariants for review

- Portable import must validate before creating or replacing the destination.
- A portable copy must remain sufficient to rebuild a deleted native cache.
- Native commands must validate workspace, revision, path, asset, and response identity at the boundary.
- Production content security policy must remain local-only unless a documented ADR and security review change it.
- New dependencies require lockfile, SBOM, audit, and license-review updates.
- Security errors must not disclose raw local paths or private workspace data.

## Release blockers

The current repository evidence still lists the cross-platform native smoke matrix as pending, and the SQLite service is not yet evidenced as integrated through every Tauri persistence path. Private vulnerability intake, supported-version policy, signing, project licensing, and complete third-party notices are also owner prerequisites. These are not waived by the existence of this threat model.
