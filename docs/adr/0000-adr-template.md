## Context

What problem, constraint, or evidence requires a decision? Include links to the affected code, format, threat, benchmark, or release gate.

## Decision

State the decision in testable terms. Name the boundary, source of truth, invariant, and any behavior that must not change.

## Compatibility and migration

Describe the format/version impact, upgrade path, downgrade behavior, unknown-field handling, backup requirement, rollback plan, and how aliases or embedded links are repaired.

## Security and privacy

Describe new trust boundaries, untrusted inputs, capability changes, data exposure, dependency impact, and residual risk. Link to the threat-model entry.

## Validation

List deterministic checks, fixtures, platform coverage, and evidence locations. A local pass is not cross-platform certification.

## Rollout and rollback

State how the change is introduced, how users recover if it fails, and the exact rollback trigger. Do not claim signing, support, or legal approval until an owner supplies evidence.
