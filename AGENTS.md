# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable Tactile Product Decisions

- Tactile is a local-first desktop/web workspace with no cloud storage in the core product. It must support portable JSON-based import/export, eventually packaged as a `.tactile`/ZIP bundle.
- The sheet is the stable spatial map. A cell is either an ordinary typed value or a reference to an embedded object; objects may nest to multiple levels (for example, a document inside a sheet inside another sheet).
- Ordinary cells are serialized together per sheet. Do not create one folder per cell; only embedded objects and binary assets receive separate IDs/files or folders.
- Embedded cells remain normal compact sheet cells. Show only the embedded object's title and one small monochrome icon—no previews, thumbnails, colored icons, badges, or expanded cards inside the grid.
- Embedded cells behave like button-like links: show a finger pointer on hover, switch to a grabbing cursor during drag, and never expose text-selection behavior on their labels.
- The visual material is a dense tray of white molded chewing-gum-like cells: very tight spacing, softly convex tops, rounded sidewalls, restrained highlights, contact shadows, and clear physical lift on hover/focus/selection. Dimensionality should come from light and elevation, not color.
- Enter an embedded object by clicking it or pressing `]` while it is focused. Press `[` to return to its parent. Navigation may be many levels deep and should use the fast origin-preserving In & Out transition.
- Every object has a title box and description box at the top. Do not impose the same persistent toolbar on every object type; tools and commands should be contextual to the active type.
- The object system must be extensible through modular type definitions so later types such as Gantt charts can be added without rewriting the workspace shell.
- Sheets must be architected for genuine spreadsheet capabilities, including ranges/grouping, conditional formatting, formulas, sorting/filtering, formatting, clipboard workflows, and undo/redo—not just a visual grid.
- Build production-grade modules under `src/`; do not concentrate the application in `App.jsx`. Ship small working browser iterations quickly and show them during development.
- Treat Obsidian's manifesto and Steph Ango's “file over app” principle as product constraints: the local copy is canonical, files must be inspectable and durable, the network is optional, and the user retains ownership, agency, privacy, backup choice, and interoperability.
- Embedded-object navigation uses a crisp staged origin-preserving transition. Clicking an embedded cell first transforms it into a floating child window occupying about 90% of the viewport while the parent sheet remains visible around the edges, then settles into full-screen when requested. The reverse transition must return to the exact source cell.
- With the two-layer In & Out render window, a parent visible around a floating child keeps its Parent action in place, but the complete underlying parent surface is inert until the child closes. Ancestors hidden behind a full child must not leave duplicate parent controls in the DOM.
- Home designation is default-entry metadata, not the active navigation root; changing home preserves the current In & Out stack, dock path order, and Parent relation.
- User-facing launch metadata is called Start: “Set as start” changes the default opening object while Home remains the first/root Tiles page; portable `homeObjectId` and `homePath` fields remain compatibility names.
- The opening transition needs an unmistakable but clean source-cell cue inspired by shared-container/app-opening motion without copying the macOS Dock effect; use the source outline/window handoff without transient address labels or moving viewport-edge contours.
- Keep familiar A1-style row and column addressing as the primary visible sheet coordinate system. Do not replace it with semantic paths, jump codes, or another novel notation unless the user revisits this decision.
- Use the warm editorial "Operating model" mock (the second August 9, 2026 visual direction) as the current visual baseline: ivory paper, carbon ink, disciplined grid, typographic hierarchy, fine rules, restrained rust focus, and subtle molded depth. The user prefers this direction over the other two but does not consider it final, so explore close coded iterations rather than treating every detail as locked.
- Continue only with the Paper visual scheme; the Carbon and Relief coded passes are no longer candidates. Deepen Paper through density, typography, and motion rather than adding more material themes.
- Call the embedded-object transition system "In & Out". `]` enters the focused embedded object and `[` returns to its parent. The intro should mirror the deliberate feel of the outro and hold at the roughly 90% semi-expanded stage long enough for the parent context and source cell to register before filling the viewport.
- Reject the current large display title and italic serif subtitle treatment. Object headers, breadcrumbs, title, and description should be markedly more compact. Typography is not selected yet; expose a practical visual font comparison before locking a family.
- Default sheet density should feel like a fast spreadsheet, not a grid of cards. Keep row height compact (the current Paper target is about 30px with 1px seams), while preserving restrained molded lift on hover, focus, and selection.
- The current typography lead is the Public Service direction: Public Sans for the Paper UI/display layer, with a Zed-inspired engineering tone. Use Lilex for formulas, cell addresses, keycaps, and other monospace text. Active cells should have one precise accent outline plus a small familiar fill handle, never the previous thick double ring.
- The actual product uses a sparse CSV-first object model. Every sheet displays at least 256 rows × 64 columns, but export writes only its used range. Embedded-cell CSV values use `[[tactile:<type>:<object-id>|<title>]]`; embedded Markdown and native files live separately and resolve through the workspace manifest.
- A new workspace starts with a blank sheet as its home object. Any object can be made home. Object subtitles are optional and must not reserve vertical space when empty; missing titles receive stable generated names.
- Right-clicking a cell opens a compact command menu containing familiar worksheet actions and Tactile creation actions such as `In: Tiles` and `In: Text`. Creating Text stores Markdown in a separate linked object.
- Opening the Markdown selected-text command menu with the mouse must preserve the editor's visible native text selection; the first arrow key may transfer focus into the menu for keyboard navigation.
- Themes are data, not hardcoded skins: tokenized themes must be locally saved and support creation, import, export, and sharing. Preserve unknown theme tokens for forward/plugin compatibility.
- Embedded-object pointer navigation has two deliberate depths: a single click opens the child and leaves it suspended as a roughly 90% floating window with the parent still visible; a double-click opens the child in full view. While a child is floating, pressing `]` again expands it fully. Pressing `[` returns to the parent from either state.
- Never expose browser- or OS-default-looking dropdowns, select boxes, text inputs, color pickers, checkboxes, switches, or sliders. All visible controls must use a coherent custom Tactile control system with compact Paper styling, explicit hover/focus/disabled states, and full keyboard behavior; hidden file inputs may remain native behind custom triggers.
- The In & Out source cue must never look like a second embedded tile laid on top of the child. Keep the parent source as an origin outline/tether without a transient address label, then let the floating child own the visible surface.
- In & Out keeps the full logical navigation history for Back/Forward, but renders only the latest two layers; entering a child from a floating parent first promotes that parent to full, then presents the child as the single floating layer.
- Restoring a saved start route materializes its complete logical parent chain immediately at the resolved leaf; staged In & Out animation is reserved for interactive navigation.
- In & Out states are browser-history states: entering a child writes a URL with its object, parent cell, and floating/full mode; browser Back returns through the nested stack and Forward reopens it. A floating child exposes a mouse-accessible Expand action that is also reachable through `]`.
- Outside-click closure is one pointer event per floating layer and carries that layer's stable key; it must remove exactly the top history entry even when adjacent object titles match.
- While a child is floating, the shell and parent-visible regions outside its window use the dismiss pointer consistently; controls inside the child retain their own cursor semantics.
- During the In & Out origin handoff, the source embedded-cell label remains visible until the child surface owns the visible window; the origin window may provide only a transparent outline/tether.
- Page spacing should stay compact and intentional: align object headers and work surfaces to the same editorial column, avoid oversized editor gutters, and preserve visible parent context around floating panes.
- Ordinary multi-cell ranges should not add an active-row/active-column crosshair outside the selected range; preserve axis tint only for single-cell context or explicit full-row/full-column selection.
- Whole-row selections tint only the selected row and whole-column selections tint only the selected column; never add perpendicular axis context from the active cell.
- Range drags must preserve the pointer endpoint at any speed: keep global gesture listeners stable across selection renders, resolve targets from sheet geometry including virtual-cell seams, capture the stable sheet surface after the drag threshold, and finalize from the pointer-up hit-test when intermediate move events are coalesced.
- Auto-fill extends each axis-aware pattern across a rectangular selection: matching vertical series continue independently in every selected column, while constant blocks repeat unchanged instead of inventing a sequence.
- README branding uses a wide ivory Paper banner built around the canonical dotted rust mark, with the exact descriptor “Fully local dimensional workspace.” Do not restore the previous “Local-first · Spatial workspace” banner line.
- README-facing visual assets should use explicit solid backgrounds for reliable light and dark GitHub rendering; transparency is reserved for in-app marks such as the dock logo and favicon. Public product naming is simply “Tactile,” without an “alpha” suffix.
- The README feature tour should remain a high-resolution 16:9 capture with focused zooms for the sheet and creation menu, followed by the floating and full In & Out states; UI labels must remain readable when GitHub scales the GIF.
- The first sheet row must lift above the sticky column rail without paint containment clipping its top edge. Replace browser-native title popovers with compact Paper tooltips; embedded cells themselves should stay quiet rather than showing verbose hover instructions.
- Active-cell outlines must be painted by a raised virtual-cell slot, so the one-pixel perimeter never disappears beneath a neighboring tile at the left or right seam.
- Formula-bar editing must preserve input focus across each controlled value update; grid auto-focus restoration is disabled while the formula bar owns editing so typing never stops after the first character.
- Worksheet cells are selection and navigation surfaces only; they never render an inline editor. Double-click, Enter/F2, and first printable-key entry route deliberate edits into the formula bar, whose leading `=` activates formula-reference mode without changing the source selection.
- Sheet formatting is a compact always-visible strip above the formula/value field, with direct fill and text color swatches, alignment, number, conditional, and clear actions; selected cells keep their active rust perimeter while retaining their row/column context and own fill tint.
- Latest feedback baseline (2026-08-10): the next visual pass must restore clear horizontal/vertical alignment and symmetry with more generous shell spacing while keeping the sheet itself dense. Remove duplicate local-save labels, the explicit Description button, and the visible “Embedded object” label. Cell editing must use the Paper/rust accent instead of browser-blue selection, with no stray-looking input box. Header selection should select a row/column without moving the active cell to the far edge. Floating children should close back to their source tile when the user clicks outside. The worksheet needs visible resize/reorder affordances, richer formatting (including text highlighting), image paste from the clipboard, and a much deeper Google Sheets-like command surface. Markdown should move toward a Google Docs-like writing flow with substantially richer blocks and shortcuts.
- Primary object surfaces use the full available viewport width. Do not center sheets, editors, documents, or file viewers inside a capped-width application shell; readable text measure may be controlled inside a full-width editor surface.
- Settings live only in the global app dock at the bottom-left. Per-object menus are reserved for object and local-workspace actions, never duplicate global appearance/settings entry points.
- Floating child panes need deliberate top breathing room between the pane edge and the child header, while keeping the header and work surface on one aligned compact rhythm.
- Cell edit entry must never flash a browser-blue value selection: focus the editor at the end of the value before paint, keep the active-cell cue to one restrained rust outline aligned to the full tile bounds, and reserve accent selection styling for deliberate text selection.
- All editable Paper controls, including the Go to tile A1 address field, use the same warm Paper selection colors instead of the browser-default blue highlight.
- Reverse In & Out must keep the child surface visible while it contracts; never expose a blank paper rectangle or an empty source-echo over the parent cell during the handoff.
- Worksheet geometry is per-axis and per-index: resizing a column or row changes only the targeted index set (or the explicitly selected set), while reorder/insert/delete operations remap those size maps with the axis.
- Virtual-sheet scrolling must be compositor-friendly and origin-preserving: sticky headers follow the native scroll offset immediately, the virtual render window refreshes before a fast wheel jump can expose a stale/blank slice, and persistence bookkeeping remains frame-coalesced.
- Document formatting controls use custom Paper popovers (never native color inputs) for text color, highlight, underline, task lists, and richer inline Markdown while keeping the toolbar compact.
- Header and footer rhythm is intentionally compact and symmetrical: aligned editorial columns, a short object header, a balanced 32px status dock, and no redundant local-save or embedded-object labels.
- Range-selected tiles should have a clearly legible warm Paper tint and inner lift, while the active tile remains the single stronger rust outline with its fill handle.
- A single active cell is signified by its rust border only: preserve its own fill/text formatting, do not wash the active row or column, and show the active address/value in the bottom status dock.
- The first data row must remain inside the sticky column-header lane during hover/selection; preserve its visual lift with shadow and border, never by translating its border under the header rail.
- Default data rows, including the first row, share one compact height and seam geometry; row-specific overrides are only for deliberate user resizing.
- The shared object title input must retain focus when editing; revealing the optional description field must never auto-focus it and steal the title keystrokes.
- Tactile's identity uses a transparent, scalable dotted tactile-field mark in warm rust; keep the same mark in the app dock and favicon, with the banner/README staying quiet and product-oriented.
- Object headers stay visually quiet: the title is the primary top-left control, the parent action is compact, and the object path belongs in the bottom Tactile dock. Dock paths show `/`-separated object titles and collapse to first-two / ellipsis / last-two after four jumps.
- Bottom-dock path segments are clickable direct jumps; when the compact path shows an ellipsis, hovering or focusing it opens the complete path above with clickable segments.
- The dock ellipsis opens a compact centered parent navigator without a heading: a solid portal-safe Paper panel with a scrollable current-to-root list, so dock separators cannot show through it at any depth.
- The Ancestry navigator sizes to its content within a viewport cap; overflowing object names stay clipped until hovered/focused, then use a restrained marquee for discovery.
- Parent entries in the portaled navigator use the finger pointer cursor to make their direct-jump behavior obvious.
- Clicking any earlier breadcrumb collapses the visible In & Out stack once, then commits directly to that ancestor route; hidden intermediate layers are removed without replaying their animations.
- The bottom Tactile dock uses a balanced 32px rhythm: the mark/name, path, history, settings, active-cell status, and sheet metadata each have deliberate internal padding and group separators rather than touching icon edges.
- Bottom-dock group separators sit in the breathing gaps between controls instead of being painted as rounded button borders; brand, history, and Settings use the same thin straight Paper rule.
- Files hierarchy feedback: keep tree indentation compact and add quiet connector guides for scanability; object icons may be customized per object with a small Paper color palette or a user-entered emoji, while embedded sheet cells retain their quiet monochrome treatment.
- Files can be pinned as a persistent left sidebar; pinned mode removes the drawer scrim, reserves workspace room for the base sheet and In & Out layers, and keeps the compact bottom dock visible.
- Files pinning and unpinning should animate the workspace reservation and scrim together, and the sidebar should expose a keyboard- and pointer-resizable edge with a workspace-persisted width.
- Files sidebar pinned state and width are portable workspace settings serialized in the `.tactile` bundle; browser-only legacy preferences may be migrated once and then discarded.
- Files tree row actions, including the icon/color customize button, stay vertically centered within the row hit area across active and nested entries.
- Files icon-customize actions are icon-only and transparent; use the rust accent on hover/focus without adding a filled button background.
- Floating Expand must align to the child header action baseline, not hover above it; title fields keep stable horizontal padding across rest, hover, and focus.
- Worksheet cell text defaults to a readable 11.5px Paper scale, with a direct custom text-size control in the always-visible tile formatting strip; size changes apply only to the selected cell range and remain local in the cell style.
- An empty focused worksheet tile seeds its first printable character through the formula bar; Enter/F2 and double-click also focus the formula bar without creating a cell-local input.
- Floating-window Expand guidance renders outside the clipped, scaled child surface so the Paper tooltip never gets cut off at the pane edge.
- Embedded tile labels resolve the linked object title live from the workspace; ordinary cells continue to display their entered value, and navigation/source cues use the same resolved label.
- Object headers have no description UI or reserved description row; descriptions may remain in portable data for compatibility but are never rendered or solicited.
- Reverse In & Out fades child content before the window reaches the source cell and suppresses the source echo during contraction, preventing a one-frame parent/child double paint.
- The browser document title always follows the active object as `Tactile — {object title}`, including nested and renamed objects.
- The bottom dock does not display the `[ ] in/out` keyboard hint; In & Out shortcuts remain available without occupying persistent status-bar space.
- Making an object home changes only the launch target; it never re-roots containment. Persist or reconstruct the object's full parent chain so reopening still preserves dock ordering and Parent navigation.
- Every embedded object has an inspectable parent link: a stable embed-link ID, containment/alias relation, parent object ID, and source cell. Navigation routes validate those links edge by edge; legacy address-only workspaces are repaired deterministically, and structural source-cell moves keep the link while updating its live address.
- Files is a shell-owned, non-resizing Paper drawer launched from one global bottom-dock control. It is independent of Home: canonical objects appear once, alias locations remain direct shortcuts, parentless objects stay discoverable, and metadata search never scans sheet cell values on each keystroke. Direct file opens use validated root-aware routes and full view; the drawer itself is transient and never exported.
- Files entries use a custom Paper context menu rather than the browser menu; actions include opening the object or parent, setting the launch/start object, expanding its hierarchy, customizing its icon, and copying its validated path.
- Files search matches object titles only; displayed paths provide location context but are not search fields.
- Files context-menu Open actions pass the selected object route explicitly, so choosing Open from a mouse or keyboard-invoked menu navigates through the same validated route as a normal Files click.
- The bottom-dock Files control toggles Files visibility in both modes; a second click hides the panel and releases reserved workspace space even when the pinned preference remains enabled, and another click restores it.
- Paper hover tips render in a document-level layer with viewport-aware placement and inherited theme tokens, so ancestor overflow and clipping cannot truncate them.
- Paper hover tips use a dedicated top-level overlay stack with collision-aware above/below placement; the overlay must stay above Files, floating windows, and clipped object surfaces while remaining inside the viewport.
- Reverse In & Out collapse keeps one circular radius on the visible child pane; never interpolate separate horizontal and vertical radii that produce stretched corner arcs. The source cell remains the rounded final handoff cue.
- During full-to-floating reverse In & Out, preserve full-view header padding, content inset, and status-bar geometry until the transform settles; the chrome must not jump independently of the pane.
- Built-in themes include the original Paper foundations plus GitHub Dark, Catppuccin Dark, Flexoki Light and Dark, One Dark, Nord Dark, VSCode Dark, macOS Light and Dark, and Notion Light and Dark. Each preset maps its recognizable palette onto Tactile's semantic surface, ink, rule, status, focus, and selection tokens while preserving compact molded tile depth.
- Settings scrollbars are compact custom controls whose track, thumb, and hover color follow the active theme tokens; never fall back to mismatched browser or OS scrollbar chrome inside the theme list or editor.
- Default worksheet ink, molded-surface highlights, and elevation shadows are semantic theme tokens. Dark themes must never inherit the light Paper ivory gradient or opaque white inset rules; explicit cell formatting remains independent from the theme-defined default ink.
- Latest feedback: Enter/F2, double-click, and first printable-key entry open a visible inline editor inside the active worksheet tile; the cell shows a caret and owns typing instead of moving focus to the top formula field.
- Native workspace folders are canonical on desktop: changing the home folder switches to that folder's workspace, while an empty folder starts a new Home sheet without copying objects from the previous folder. Portable export is ZIP-only in the user interface, and Settings provides change-folder and open-folder actions.
